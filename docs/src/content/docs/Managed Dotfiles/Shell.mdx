Homebrew bash 5 is the login shell. The whole configuration is one file.

## `~/.bashrc`

```bash
# Agent-first shell. No completions, no plugins; starship draws the prompt for humans only.
# mise shims first so every tool resolves without `mise activate`, even in `bash -c`.
export PATH="$HOME/.local/share/mise/shims:$HOME/.local/bin:$HOME/.bun/bin:/opt/homebrew/bin:/opt/homebrew/sbin:$PATH"

# The one place that knows how coding agents mark their shells. Add or fix agents here only.
# Claude Code reads this file once, before its tool shells exist, to fix their PATH: all it has set then is
# CLAUDE_CODE_ENTRYPOINT. CLAUDECODE comes later, in the tool shells, which do not read this file again.
is_agent() { [ -n "${CLAUDECODE:-}${CLAUDE_CODE_ENTRYPOINT:-}${CODEX_THREAD_ID:-}${ANTIGRAVITY_AGENT:-}" ]; }
# Agents get ~/.local/agent-bin first: an `op` that uses Connect and a service account instead of Touch ID.
is_agent && PATH="$HOME/.local/agent-bin:$PATH"

export EDITOR="code --wait"
export VISUAL="$EDITOR"
export HOMEBREW_NO_ENV_HINTS=1
# Shared iOS simulator pool size on this Mac (was in the old .zshenv).
export IOS_SIMULATOR_POOL_SIZE="${IOS_SIMULATOR_POOL_SIZE:-3}"

# Secrets stay out of the repo. Create ~/.config/secrets.env (chmod 600) with `export NAME=value` lines.
for f in "$HOME/.config/secrets.env" "$HOME/.codex/secrets/linear.env" "$HOME/.config/work/env.sh"; do
  [ -r "$f" ] && . "$f"
done

case $- in *i*)
  alias claude='command claude --dangerously-skip-permissions'
  alias agy='command agy --dangerously-skip-permissions'
  alias maude='clear; ssh -t maude cc'

  # .zshenv sources this file in sh emulation; zsh cannot run the bash prompt code
  if [ -n "$BASH_VERSION" ]; then
    if is_agent || [ "$TERM_PROGRAM" = claude-desktop ]; then
      PS1='\w \$ '
    elif starship=$(command -v starship); then
      # `starship init` costs a process per shell; cache its output, keyed to the installed binary
      starship=$(readlink -f "$starship")
      init="$HOME/.cache/starship/init.bash"
      if [ "$(head -n 1 "$init" 2>/dev/null)" != "# $starship" ]; then
        mkdir -p "${init%/*}"
        { echo "# $starship"; "$starship" init bash --print-full-init; } > "$init"
      fi
      . "$init"
    fi
    unset starship init
  fi
  ;;
esac
```

- mise shims come first so every tool resolves without `mise activate`, including in `bash -c`.
- `is_agent` is the one check for "a coding agent runs this shell". It reads the variables each agent sets: `CLAUDECODE` and `CLAUDE_CODE_ENTRYPOINT` (Claude Code), `CODEX_THREAD_ID` (Codex), `ANTIGRAVITY_AGENT` (Antigravity). Claude Code needs both: it reads the profile once to fix its tool shells' `PATH`, when only `CLAUDE_CODE_ENTRYPOINT` is set, and sets `CLAUDECODE` in the tool shells afterwards. Add or fix an agent there only.
- Agent shells get `~/.local/agent-bin` first on `PATH`. See [1Password for agents](#1password-for-agents).
- `~/.config/secrets.env` is where API keys go. It is untracked and mode 600. The Codex secrets file is sourced too so both agents see the same variables.
- `~/.config/work/env.sh` exists only on work machines; see the work profile in `AGENTS.md`.
- Everything under `case $- in *i*)` runs only in interactive shells. `bash -c` and agent tool calls never reach it.

## Prompt

Interactive bash picks one of two prompts:

| Shell | Prompt |
|---|---|
| `is_agent`, or the Claude desktop Terminal panel (`TERM_PROGRAM=claude-desktop`) | `\w \$ `, no colors |
| Any other interactive bash (Ghostty) | starship |

`~/.config/starship.toml` renders only three modules: the folder (last three segments, bold purple), the duration of commands that ran 2 s or longer, and a `❯` that is green after success and red after a failure. Git, language, and cloud modules are not in `format`, so starship never scans for them.

`starship init bash` would cost a process per new shell, so `~/.bashrc` writes its output to `~/.cache/starship/init.bash` once. The first line records the resolved starship binary path; when `brew upgrade` moves starship to a new Cellar path, the next shell regenerates the cache. Starship comes from Homebrew rather than mise so each prompt runs the binary directly instead of through a shim.

Measured on a work Mac: a new interactive shell takes about 53 ms with the cached starship init, 27 ms with the plain prompt, and 104 ms with an uncached `eval "$(starship init bash)"`. Each prompt render takes about 10 ms.

`~/.bash_profile` sources `~/.bashrc`, so login shells and interactive shells are identical.

## 1Password for agents

Agents read and write 1Password without Touch ID; your own `op` still uses the desktop app and Touch ID.

`~/.local/agent-bin/op` sits ahead of the real `op` only in agent shells. It picks the credentials per command:

| Command | Credentials | Why |
|---|---|---|
| `op read`, `op inject`, `op run`, `op item get --format json` | 1Password Connect | The only commands the CLI runs over Connect; no rate limit |
| everything else | service account | Full CLI; counts toward the plan's daily request cap |

The wrapper reads `OP_AGENT_CONNECT_HOST`, `OP_AGENT_CONNECT_TOKEN` and `OP_AGENT_SA_TOKEN` from `~/.config/op/agent.env` (untracked, mode 600). It is not `~/.config/secrets.env`, because that file is sourced into human shells too, and `OP_SERVICE_ACCOUNT_TOKEN` there would take over your own `op`. Without the file the wrapper runs the real `op` unchanged. `tests/test_agent_op.py` covers the routing.

## `~/.zshenv`

```zsh
emulate sh -c '. "$HOME/.bashrc"'
```

Anything that still runs `zsh -c` gets the same PATH and secrets. There is no `.zshrc`.

## How agents pick the shell

- **Codex** reads the login shell from the user record. After `chsh` it uses bash immediately.
- **Claude Code** uses `$SHELL`. `CLAUDE_CODE_SHELL` is pinned to `/opt/homebrew/bin/bash` in its settings so it does not depend on the parent process.
- **T3 Code** and other GUI apps inherit `SHELL` from the login session. `run_once_after_set-login-shell` sets it with `launchctl setenv` so apps launched after the switch get bash without logging out.

## Login shell on a new machine

`run_once_after_set-login-shell` adds `/opt/homebrew/bin/bash` to `/etc/shells`, runs `chsh`, and sets the launchd variable. It asks for `sudo` once.
