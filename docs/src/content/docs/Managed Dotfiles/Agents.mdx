## Claude Code

`~/.claude/settings.json` is tracked as a plain file.

- `CLAUDE_CODE_SHELL` pins the Bash tool to Homebrew bash.
- `skipDangerousModePermissionPrompt` is on; the shell alias adds `--dangerously-skip-permissions`.
- Plugins: ponytail, i-have-adhd, frontend-design.
- Hooks: the T3 PR watch hooks below.

## T3 PR watch hooks

T3 Code runs Claude Code, Codex and Antigravity. In a T3 thread (`T3CODE_THREAD_ID` set), each of them runs `~/.agents/hooks/t3-pr-watch.sh`, which answers each agent's hook events in its own format:

| Agent | Registered in | Events |
|---|---|---|
| Claude Code | `~/.claude/settings.json` | `SessionStart` (compact, resume), `Stop`, `UserPromptSubmit` |
| Codex | `~/.codex/hooks.json` | `SessionStart`, `Stop`, `UserPromptSubmit` |
| Antigravity | `~/.gemini/config/hooks.json` | `SessionStart`, `Stop` |

- **Stop**: the script reads the thread with `t3 thread show --json`. When an open PR linked to the thread is not watched, and `gh pr view` confirms it is still open (T3's snapshot lags a merge), it keeps the turn going once with a reason that names the PR. The agent then re-arms the watch, or ends the turn again if it handed the PR back on purpose. T3's own wake text tells the agent not to list a PR again, so the end-of-turn check cannot rely on instructions alone. A turn the hook already extended stops: Claude Code and Codex send `stop_hook_active`; Antigravity documents `continuationActive` but leaves it false, so the script reads `executionNum > 0` instead. An Antigravity stop the user cancelled or an error caused is left alone.
- **Guard**: at each turn end the script also starts `~/.agents/hooks/t3-pr-watch-guard.sh` detached, one per thread, with its pid in `~/.local/state/t3-pr-watch-guard/`. A Stop press on an idle T3 thread unwatches every PR, and no hook runs until the next message. The guard reads the thread every 30 seconds. When a PR it saw watched is still open but unwatched and no turn has run since, it sends the thread a `t3 thread send` message to re-arm the watch. An unwatch the agent makes happens inside a turn, which ends the guard. It also exits when the thread settles or archives, nothing open stays watched, or after 24 hours.
- **UserPromptSubmit** (Claude Code, Codex): T3's Stop button on a thread that is only watching sends `watching: false` for every watched PR on it. When the next prompt arrives and an open linked PR is unwatched, the hook adds context telling the turn to re-arm `watch_pull_request` (until merged) and read the PR's checks first. Antigravity has no prompt event; the guard covers it.
- **SessionStart**: in a thread with an open PR, it reminds the agent that a summary saying a PR is watched is not proof, and to re-check with `list_thread_pull_requests`.
- Codex runs a new or changed hook only after you approve it once with `/hooks` in the Codex TUI; it records the approval as a `trusted_hash` in `~/.codex/config.toml`.
- `tests/test_t3_pr_watch.py` covers each agent's output format and loop guard.

## MCP servers and skills

Every agent gets the same three MCP servers: kanvil, github-scheduler and t3-factory. Their tokens live in Secret Drop files. Claude Code and Codex read them through a header helper. Antigravity has no header helper, so its config runs `~/.local/bin/mcp-bridge <secret name> <url>`: a stdio bridge (`mcp-remote`) that reads the token from Secret Drop and keeps it out of argv and agent config. Register a server with `agy mcp add`. Its config, `~/.gemini/config/mcp_config.json`, is app-owned and untracked, like `~/.codex/config.toml`.

`run_onchange_after_link-skills` links every skill into `~/.claude/skills` (Claude Code), `~/.codex/skills` (Codex) and `~/.agents/skills` (Antigravity).

## Global instructions

One source, `dotfiles/.chezmoitemplates/agent-instructions.md`, renders a copy for each agent:

| File | Read by | Agent |
|---|---|---|
| `~/.claude/CLAUDE.md` | Claude Code | `claude` |
| `~/.codex/AGENTS.md` | Codex | `codex` |
| `~/.gemini/GEMINI.md` | Antigravity | `antigravity` |

The table at the top of the template records what each agent has, so far only whether it has the kanvil, github-scheduler and t3-factory MCP servers; today all of them do. A section that needs a tool wraps itself in `{{ if $mcp }}…{{ else }}…{{ end }}`. When an agent gains or loses a tool, change its entry there; a new agent gets an entry and a file that passes its name, and an unknown name fails `chezmoi apply`. Edit the template, then `chezmoi apply`; edits to the rendered files are overwritten. Work machines render the encrypted work copy into all three files instead.

Agents link Kanvil tickets directly in chat and skip T3 Code's issue sidebar for those tickets.

Memory, history, and project state under `~/.claude` are not tracked.

## Skills

Shared skills live in [`kiliantyler/skills`](https://github.com/kiliantyler/skills), checked out at `~/git/kiliantyler/skills`. `run_onchange_after_link-skills` clones that repo if it is missing, links each `skills/<name>/` into `~/.claude/skills`, `~/.codex/skills` and `~/.agents/skills`, and unlinks repo skills that were deleted. It never pulls the repo, and it leaves alone any entry that is not a link into it (third-party installs, plugin links), printing a note when one shadows a repo skill of the same name. It re-runs when `gh` sign-in, the checkout's presence, or the repo's list of skills changes, so a new or deleted skill is linked or unlinked on the next apply and `chezmoi status` stays empty otherwise.

## Codex

The global instructions send every home-directory change through the `dotfiles` skill in `kiliantyler/skills`, which walks the chezmoi workflow in this repo. They also tell agents to pass secrets by `op://` reference through `op run`, `op inject` or `op read`, which the [agent `op`](/managed-dotfiles/shell#1password-for-agents) serves without Touch ID. Under `~/.codex` only `AGENTS.md` and `hooks.json` are tracked. Codex reads the login shell from the user record and its own secrets from `~/.codex/secrets/`, which `~/.bashrc` also sources so both agents share variables.

## Local validation

Builds and tests run directly on the host with each repository's documented commands and local services. The Tart build VM and `macos-build` wrapper are retired. The global instructions are shared by Codex and Claude Code.

## VS Code

`~/Library/Application Support/Code/User/settings.json` is tracked. VS Code rewrites it when settings change in the UI, so after a change run:

```sh
chezmoi re-add "$HOME/Library/Application Support/Code/User/settings.json"
```

Extensions are not tracked.

## Deployer registrations

The Mac's deployer installs releases for every app with a file in `~/.config/deployer/conf.d/<app>.env`; each holds the app's `REPOSITORY=`. chezmoi tracks these files so a rebuilt Mac keeps every registration. `t3-factory.env.tmpl` writes its home-directory paths through `{{ .chezmoi.homeDir }}`.

Register a new app by writing its file, then track it:

```sh
chezmoi add ~/.config/deployer/conf.d/<app>.env
```

The directory is not `exact_`, so a registration that is not tracked yet survives `chezmoi apply`. `~/.config/deployer/webhook-secret` is a secret and stays untracked. Caddy's `~/.config/caddy/conf.d/*.caddy` stays untracked too: each app's `install-release` writes its own site file there.
