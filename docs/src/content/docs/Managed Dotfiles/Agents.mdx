## Claude Code

`~/.claude/settings.json` is tracked as a plain file.

- `CLAUDE_CODE_SHELL` pins the Bash tool to Homebrew bash.
- `skipDangerousModePermissionPrompt` is on; the shell alias adds `--dangerously-skip-permissions`.
- Plugins: ponytail, i-have-adhd, frontend-design.
- A `SessionStart` hook runs on `compact` and `resume`. In a T3 Code thread (`T3CODE_THREAD_ID` set), it tells the agent to call `list_thread_pull_requests` and re-arm any PR it still waits on that shows `watching: false`. A T3 PR watch can drop without notice, and a summary that says a PR is still watched is not proof that it is.
- A `Stop` hook, `~/.claude/hooks/t3-pr-watch-stop.sh`, runs when a turn ends in a T3 Code thread. It reads the thread with `t3 thread show --json`, and when an open PR linked to the thread is not watched, and `gh pr view` confirms it is still open (T3's snapshot lags a merge), it blocks the stop once with a reason that names the PR. The agent then re-arms the watch, or ends the turn again if it handed the PR back on purpose. T3's own wake text tells the agent not to list a PR again, so the end-of-turn check cannot rely on instructions alone.
- At each turn end that hook also starts `~/.claude/hooks/t3-pr-watch-guard.sh` detached, one per thread, with its pid in `~/.local/state/t3-pr-watch-guard/`. A Stop press on an idle T3 thread unwatches every PR, and no hook runs until the next message. The guard reads the thread every 30 seconds. When a PR it saw watched is still open but unwatched and no turn has run since, it sends the thread a `t3 thread send` message to re-arm the watch. An unwatch the agent makes happens inside a turn, which ends the guard. It also exits when the thread settles or archives, nothing open stays watched, or after 24 hours.
- The same script runs as a `UserPromptSubmit` hook. T3's Stop button on a thread that is only watching sends `watching: false` for every watched PR on it, so a Stop before a message silently drops the watch. When the prompt arrives and an open linked PR is unwatched, the hook adds context telling the turn to re-arm `watch_pull_request` (until merged) and read the PR's checks first.
- `~/.claude/skills/nano-banana` generates images through the Gemini CLI, which mise installs. It needs `GEMINI_API_KEY` in `~/.config/secrets.env`.

`~/.claude/CLAUDE.md` holds one line, `@~/.codex/AGENTS.md`, so Claude Code reads the same global instructions as Codex.

Memory, history, and project state under `~/.claude` are not tracked.

## Skills

Shared skills live in [`kiliantyler/skills`](https://github.com/kiliantyler/skills), checked out at `~/git/kiliantyler/skills`. `run_onchange_after_link-skills` clones that repo if it is missing, links each `skills/<name>/` into `~/.claude/skills`, `~/.codex/skills` and `~/.agents/skills`, and unlinks repo skills that were deleted. It never pulls the repo, and it leaves alone any entry that is not a link into it (third-party installs, plugin links), printing a note when one shadows a repo skill of the same name. It re-runs when `gh` sign-in, the checkout's presence, or the repo's list of skills changes, so a new or deleted skill is linked or unlinked on the next apply and `chezmoi status` stays empty otherwise.

## Codex

`~/.codex/AGENTS.md` is tracked: the global agent instructions both Codex and Claude Code load in every session. They send every home-directory change through the `dotfiles` skill in `kiliantyler/skills`, which walks the chezmoi workflow in this repo. They also tell agents to pass secrets by `op://` reference through `op run`, `op inject` or `op read`, which the [agent `op`](/managed-dotfiles/shell#1password-for-agents) serves without Touch ID. Edit it in place, then run `chezmoi re-add ~/.codex/AGENTS.md`. Nothing else under `~/.codex` is tracked. Codex reads the login shell from the user record and its own secrets from `~/.codex/secrets/`, which `~/.bashrc` also sources so both agents share variables.

## Local validation

Builds and tests run directly on the host with each repository's documented commands and local services. The Tart build VM and `macos-build` wrapper are retired. The global instructions are shared by Codex and Claude Code.

## VS Code

`~/Library/Application Support/Code/User/settings.json` is tracked. VS Code rewrites it when settings change in the UI, so after a change run:

```sh
chezmoi re-add "$HOME/Library/Application Support/Code/User/settings.json"
```

Extensions are not tracked.

## Ghostty

`~/.config/ghostty/config` and the Dracula theme. Ghostty runs the login shell, so it opens bash with no further setup.
